# Vocabulary-conditioned exemplar retrieval

Notes on the examples-only follow-up: does choosing exemplars for the test
item's vocabulary rescue examples-only translation?

## Design

The paper's examples-only ablation shows every item the *first* `k`
sentences of its grammar's held-out shot pool, so which words an item sees
is an accident of pool order. The vocabulary-conditioned condition holds the
5,040 evaluation targets fixed (verified byte-identical) and instead
retrieves, per item, the `k` pool sentences covering the most of that item's
source vocabulary.

The retriever reads only the source side of the test item and the source
sides of the candidates, both available at inference time. It is a
realistic retrieval policy, not an oracle with access to the gold target.

Generated by `scripts/generate_vocab_matched_batchfiles.py`
(`--pool-prefix shots` for the shipped 18-sentence pool, `bigshots` for the
large pools). Scored by `scripts/figures/analyze_vocab_matched_ablation.py`.

## Result 1: the coverage ceiling is exact, not statistical

No item whose source vocabulary is not fully covered is *ever* translated
correctly. Across every cell run so far — random `k`=1,2,4,8,16 and
vocabulary-conditioned `k`=8,16 — that is 30,634 uncovered items with
exactly zero correct answers. Accuracy therefore factorizes identically:

    accuracy = coverage x accuracy-given-covered

| condition | coverage | acc given covered | product | observed |
|---|---|---|---|---|
| random k=8 | 8.81% | 24.55% | 2.16% | 2.16% |
| random k=16 | 25.95% | 28.13% | 7.30% | 7.30% |
| vocab-matched k=8 | 28.21% | 17.86% | 5.04% | 5.04% |
| vocab-matched k=16 | 28.21% | 27.14% | 7.66% | 7.66% |

## Result 2: which exemplars you retrieve does not matter

Random `k`=16's 1,308 covered items are a strict **subset** of
vocabulary-conditioned `k`=16's 1,422, so the two can be compared on
identical items with no selection confound.

On those same 1,308 items: random 28.13%, vocab-matched 27.60%. Difference
**-0.54 pp**, cluster bootstrap over 38 grammars 95% CI [-1.99, +0.81],
p = 0.50 (McNemar p = 0.55, 46 vs 53 discordant).

Targeting exemplars at the test item's vocabulary buys **only the coverage
it adds** (25.95% to 28.21%) and nothing in translation quality. Retrieval
does not help the model translate better; it only makes more items
translatable in principle.

## Result 3: how many exemplars you show does matter

Vocabulary-conditioned `k`=8 and `k`=16 cover the *identical* 1,422 items,
so this comparison pins coverage exactly and varies only `k`.

On the shared 1,308: `k`=8 gives 18.35%, `k`=16 gives 27.60%. Difference
**+9.25 pp**, 95% CI [+2.96, +16.86], p = 0.0002 (McNemar p = 7e-21, 150 vs
29 discordant).

So exemplar *count* carries real information beyond vocabulary — plausibly
about word order and morphology — while exemplar *choice* does not.

## Result 4: the 18-sentence pool confines the whole condition to small grammars

Coverage by lexicon size, `k`=16:

| lexicon | random cov | vocab-matched cov | vocab-matched acc |
|---:|---:|---:|---:|
| 30 | 91.4% | 91.4% | 31.8% |
| 50 | 59.2% | 66.1% | 14.9% |
| 90 | 23.3% | 30.4% | 6.2% |
| 810 | 2.6% | 2.8% | 0.1% |
| 4,010 | 2.2% | 2.8% | 0.3% |
| 6,010 | 1.2% | 1.7% | 0.1% |
| 8,010 | 1.7% | 2.4% | 0.1% |

Above ~100 lexical items, coverage is nil whatever the selection rule, so
every examples-only number in the paper is carried by the three smallest
grammars. `accuracy-given-covered` is likewise mostly a small-grammar
measurement, which is why it should not be read across cells with different
coverage.

This is the main reason to want large pools: they are the only way to
measure examples-only translation at realistic grammar sizes at all.

## Pool sizing for ~100% coverage

Probing showed the 16-exemplar budget is **never** the binding constraint.
The fraction of items greedy selection packs into 16 exemplars exactly
equals the fraction whose every source word appears anywhere in the pool.
Coverage is purely a pool-size question, and it scales with the lexicon:

| lexicon | pool 1,200 | pool 3,000 | pool 8,000 |
|---:|---:|---:|---:|
| 30 | 100.0% | - | - |
| 810 | 93.3% | 100.0% | - |
| 8,010 | 34.2% | 56.7% | 87.5% |

`scripts/generate_highcoverage_pools.py` grows each pool until coverage
reaches the target. Sampling dominates the cost (~98s per 2,000 sentences
at 8,010 items, against ~0.2s to score coverage), so grammars run in
parallel across cores with per-grammar deterministic seeds.

Two safeguards:

- **Leakage.** A large pool eventually contains a sentence whose source
  equals an evaluation item's. A vocabulary-targeted retriever would
  preferentially return exactly that sentence, and its exemplar line would
  hand over the gold translation. Any pool sentence matching *any*
  evaluation source is dropped.
- **Duplication.** Pools are deduplicated by source string, so repeated
  low-depth samples do not consume prompt budget without adding vocabulary.

## Bearing on the paper

These results strengthen the existing argument rather than complicating it.
The paper says examples are a poor substitute for the grammar; the natural
objection is that the exemplars were not *chosen well*. Choosing them as
well as the pool allows changes nothing once coverage is held fixed. What
bounds examples-only translation is vocabulary coverage, and within
coverage, how many pairs the model sees — not how well targeted they are.
